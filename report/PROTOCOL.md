# Evaluation protocol for the report

This protocol was fixed before the confirmatory runs it describes; the git history of this file is the record of that. Deviations are reported as deviations. Results live in the numbered chapters under `report/` (format: [`AGENTS.md`](AGENTS.md)).

## Backends

- **Reference**: `TaHForCausalLM` with `TaHForCasualLM_generate` (`--backend tah`). The correctness oracle; its code is not modified.
- **Engine**: `tah.engine` (`--backend tah_engine`), CUDA graphs on, `torch.compile` off. The engine version is frozen for all runs of one comparison (baseline and every checkpoint compared against it). If the engine changes, the baseline is re-run.

## R1 — engine equivalence to the reference

Evidence is reported at two levels.

1. **Mechanism level**: teacher-forced per-token decisions and logits of the engine vs the reference, judged against the reference's own numerical self-noise (bf16, different execution layouts) on the same token sequences: dataset fixtures, model-generated sequences up to ~4k positions, and long-context position buckets. Sampler distributions are compared on real logits.
2. **End-to-end accuracy (confirmatory)**:
   - Workload: MATH500 problems [0, 200) and GPQA-Diamond (all 198), 2 samples per problem, `max_new_tokens` 4096, temperature 0.6, top_p 0.95, top_k 20, decider threshold 0.9 (config `script/tah/recipes/qwen3_1.7/eval_tah.yaml` with `repeat_size: 2`).
   - Runs: reference with seed 1234 (confirmatory run); engine with seeds 42, 1234, 2024. An earlier reference run (seed 42) and earlier engine comparisons are reported as exploratory; they motivated the confirmatory run.
   - Analysis unit is the problem. Per problem, accuracy is the mean over all samples of a backend (runs × repeats); d_p = engine − reference. The estimate is the mean of d_p over problems with a paired standard error from the problem-level spread. Primary analysis: both datasets pooled (398 problems). Secondary: per dataset.
   - Equivalence test (TOST): the 90% confidence interval of the pooled difference must lie inside **±3 percentage points**. Also reported: reference vs reference (the two reference runs, same analysis) as the scale of run-to-run noise; mean iterations per generated token (engine/reference ratio within ±10%).
   - If the interval is not inside the margin, the result is reported as "equivalence not shown", with the estimate. Runs are not repeated until a test passes.

## R1-O — numerical accuracy against a high-precision oracle

Added 2026-10-13, before any oracle or coupled-sampling run. It states the R1 claim directly: **the engine's numerical error relative to the exact TaH computation is no larger than the reference's.** Margins: δ = 10% (relative), ±1 pp (accuracy under coupling). Tools live in `script/tah/validation/`; the engine and the reference model code are not modified.

**Oracle.** The unmodified reference implementation loaded in float32 (TF32 disabled). The decider threshold stays at the checkpoint's effective value bf16(0.9) = 0.8984375, a model constant, not precision. Validity check first: on a subset (≥ 20 sequences, ≥ 20k positions) the float32-vs-float64 oracle difference must be ≤ 1/20 of the reference's bf16 error on every primary metric; otherwise the float64 oracle is used.

**Implementations compared to the oracle.** Reference bf16 in the layout used for evaluations (incremental cached decoding, batch 8, left padding) — the primary comparator — and batch 1 (reported). Engine bf16 through its production cached decode path with realistic batches (≥ 32 resident requests, mixed depths). CUDA graphs, overlap scheduling and swap/restore are covered by their bitwise identity tests to this path and are not re-measured.

### R1-O1 — per-step error (teacher forcing)
- Sequences: ≥ 200 model-generated sequences (MATH500, GPQA-Diamond, HumanEval+/MBPP+), half generated by the reference and half by the engine, lengths up to 8192 tokens, ≥ 500k generated positions in total; checkpoint TaH-plus-1.7B (primary) and the synthetic `mlp3` fixture (secondary: more passes, more decisions near the threshold).
- Modes: **forced decisions** (the oracle's decisions imposed on every implementation; pure numerical error) and **free decisions** (each implementation decides itself).
- Primary metrics (forced mode, mean over positions): M1 total-variation distance between the implementation's sampling distribution (temperature 0.6, top-k 20, top-p 0.95, each implementation's own sampler) and the oracle's; M2 absolute error of the decider continue-probability per pass; M3 full-vocabulary logit RMSE.
- Criterion (non-inferiority): for each of M1–M3, the one-sided 95% upper bound of the ratio engine error / reference error ≤ 1 + δ, by cluster bootstrap over sequences (10,000 resamples, fixed seed).
- Bias: the signed decider-probability error (engine minus oracle) must satisfy |engine bias| upper 95% bound ≤ (1 + δ)·|reference bias| + 0.1·(reference M2).
- No large errors (free mode): at every position where an implementation's decision or top-1 token differs from the oracle's, record the oracle margin (|p − threshold|, or the top-1/top-2 logit gap). Criterion: the largest margin at an engine disagreement ≤ (1 + δ) × the largest margin at a reference disagreement — every engine disagreement is a near-tie of the same size the reference has.
- Secondary (reported): max absolute logit error, decision and top-1 disagreement rates, mean passes per token, everything per dataset, position bucket and pass depth; reference batch 1 as comparator.

### R1-O2 — whole trajectories with common random numbers
- Coupling: every implementation draws its token by inverse CDF from its own sampling distribution with the same uniform per (request, generated position), taken from the engine's counter-based RNG. On the reference and oracle side `torch.multinomial` is replaced by this inverse-CDF draw inside the validation tool only; the sampling distribution is unchanged. Trajectories then coincide until a numerical difference changes a token.
- Workload: MATH500 [0, 200) and GPQA-Diamond (198), one sample, `max_new_tokens` 4096, decider threshold as above, uniform stream seed 42. Oracle trajectories on the first 50 problems of each dataset.
- C1 (divergence from the oracle): per problem, the number of tokens generated before the trajectory first differs from the oracle's (capped at the generated length). Criterion: paired mean difference engine minus reference, 95% lower bound ≥ −δ × reference mean.
- C2 (accuracy under coupling): engine vs reference, paired per problem, TOST: the 90% confidence interval of the pooled difference inside **±1 percentage point**.

**Amendment (2026-10-13, before any oracle or coupled-sampling measurement on the TaH checkpoints).** Found while building and testing the tools on tiny CPU models; no R1-O data existed.
1. *Oracle model constants.* Besides the decider threshold, the oracle keeps the rotary-embedding inverse frequencies (`inv_freq`) rounded to bf16 exactly as the evaluated reference holds them. Both the reference and the engine use the rounded values; an oracle with unrounded values would add an identical error component to both and pull the error ratio towards 1, weakening the test. Only arithmetic precision differs between the oracle and the implementations.
2. *Bias criterion, paired form.* The criterion above compares a bootstrap upper bound for the engine with a point estimate for the reference, which fails even for two bitwise-identical implementations. It is replaced by: with D = |engine bias| − (1 + δ)·|reference bias| − 0.1·(reference M2), computed per bootstrap resample (the same cluster resamples for both implementations), the one-sided 95% upper bound of D must be ≤ 0.

**Amendment (2026-10-15, after the diagnostic pilots, before any confirmatory R1-O data).** Sizes were set from pilot timings and variances before any confirmatory data; no pilot effect estimate was used for sizing. The oracle constants and paired-bias amendment remain unchanged. R1-O1 initially uses 64 sequences and at least 160,000 generated positions, half reference-generated and half engine-generated, covering MATH500, GPQA-Diamond, HumanEval+ and MBPP+. A fixed optional increment of 136 gives a maximum 200 sequences and at least 500,000 positions; total teacher-forced length remains at most 8192. Forced and free modes each start on the same 64 IDs and may independently receive the same frozen 136-ID increment. Oracle validity uses 20 sequences and at least 20,000 positions; reference batch 1 is a four-sequence secondary; mlp3 is omitted.

M1–M3, paired bias and the calibrated tail criteria below each use two prespecified looks at 64/200, each at one-sided alpha .025 (97.5% bounds), 10,000 paired sequence bootstrap resamples, seed 20261013. Each criterion's success stops it permanently. Unresolved forced criteria trigger exactly +136 forced sequences; unresolved tail criteria independently trigger reference-b8 free and engine-free runs on those same fixed +136 sequences. Pool the respective mode's immutable stage shards at the second look, preserving each shard's oracle pairing. A successful mode receives no increment just because the other is unresolved; successful individual criteria retain their first-look decisions. The oracle increment is shared when both modes continue. Invalid oracle arithmetic stops the entire study; no maximum-margin verdict can stop it. Otherwise take the applicable fixed increment when unresolved, report PASS or “not shown” at the maximum, and make no discretionary extensions or reruns to obtain a pass. Margins remain delta = 10% and the existing paired-bias rule.

C2, the ±1-percentage-point coupled-accuracy criterion, is withdrawn before confirmatory data: the coupled pilots' trajectories separate after roughly 50 tokens and their correctness discordance implies a requirement of order 10,000 independent problems. No ±1 pp accuracy-equivalence claim is made. C1 is retained with a 512-new-token cap, identical counter-based uniforms and first-divergence prefixes capped at generated length. The frozen workload initially contains all 692 MATH500/GPQA problems with chat-rendered prompt length <=675 tokens (498/194); longer prompts are excluded solely by that prespecified memory envelope. If unresolved, add exactly 512 GSM8K problems selected before generation by the documented seeded-hash rule, for a maximum 1204; no stage-1 data are changed. Report censoring at 512 and early termination separately. C1 has two one-sided alpha .025 looks: require its paired lower 97.5% bootstrap bound for engine-minus-reference mean prefix to be at least −.10 times the observed reference mean. Stop permanently for success, or for futility if even the best possible remaining prefixes cannot pass; otherwise take the fixed increment. The lower bound is no greater than the observed difference. The expanded-stage estimand is the stated pooled workload. C1 and the two O1 modes have independent continuation decisions, subject to the common validity prerequisite.

The registered maximum oracle-margin disagreement rule is computed and reported in full, including both verdicts and any failures, but is **not binding, not part of the R1-O conclusion, and not a futility gate**. This demotion and the following calibrated tail criterion were both decided **after diagnostic pilots and before any confirmatory data**. The diagnostic split the same engine implementation's sequences into random halves: the maximum rule reported “not shown” in 50.0% of decision comparisons and 49.9% of top-1 comparisons. It supplies no calibrated sampling-error rate for non-inferiority, so binding the entire package to that extreme-value rule is not justified.

For decision margins and top-1 gaps separately, compute each sequence's 90th-percentile oracle margin at its disagreements (inverse empirical CDF; 0 if none), then average equally over sequences. These calibrated tail tests are binding. Require an upper 97.5% studentized paired sequence-bootstrap bound on engine mean minus 1.10 times reference mean to be <=0 at either of the two looks above. Invert the lower .025 bootstrap-t quantile, using the Student-t .975 critical value with n−1 degrees of freedom as a conservative floor. Fewer than 20 events in either implementation is inconclusive and may trigger the fixed increment at the first look. Report the CPU random-half self-comparison diagnostic, distinguishing false alarms from non-inferiority power. Also run one additional engine-free comparison on the initial 64 sequences with reversed request order/block 64/resident 32, including maximum/tail verdicts and measured correlations. This descriptive composition demonstration retains its original diagnostic confidence and is not an additional engine/reference look; it is not repeated for a preferred outcome.

Under the amended design, numerical-accuracy evidence requires the forced mean-error/bias criteria, both calibrated tail criteria, valid oracle arithmetic and short C1, alongside the existing mechanism-level evidence. Maximum-margin results remain descriptive. An unresolved binding criterion is reported as “not shown.” The independent R1 accuracy comparison remains reported separately; the withdrawn C2 cannot support an accuracy claim.

**R1 conclusion.** The engine is reported as numerically equivalent to the reference if R1-O1, R1-O2 and the mechanism-level evidence above pass; the independent-sample accuracy test (R1, ±3 pp) is reported alongside. A failed criterion is reported as "not shown" with its estimate; runs are not repeated until a test passes.

**Amendment (2026-10-14, after the seed-42 code results, before any run with the new prompt).** The harness's code prompt (TaH v1 harness, 2025-11) forces the answer to start with a code block (`reasoning=False`), so the model writes code without chain-of-thought. The paper states "pass@1 under a zero-shot CoT setting" and gives no code prompt. Under the harness prompt, MBPP+ scores 38.9 against the paper's 57.5 (Standard Qwen3-1.7B: 51.9). 51% of failures define the function under a different name than the test calls. The authors' later harness (`tah2/evaluate/codeeval.py`, 2026-10) uses benchmark-specific templates with chain-of-thought (`reasoning=True`; the MBPP template requires the function name and signature of the test cases). Therefore:
1. The R2 runs above stay as registered; their HumanEval+/MBPP+ results are reported as "harness prompt".
2. Additional runs: HumanEval+ and MBPP+ with the TaH2 code prompt (rendered identically to `tah2/evaluate/codeeval.py` with `reasoning=True`), otherwise the same settings (8192 tokens, 1 sample, temperature 0.6, top-p 0.95, top-k 20, same graders), seeds 42, 1234, 2024, same frozen engine.
3. For HumanEval+ and MBPP+, the paper comparison (reproduced or gap) uses these TaH2-prompt runs. The harness-prompt results are reported alongside. The 9-benchmark average is reported both ways.

## Later checkpoints (e.g. RL-trained deciders)

Evaluated with exactly the R2 protocol, the same seeds and the same frozen engine, and compared to the R2 baseline with the paired per-problem analysis of R1 (difference with confidence interval). They are not compared against reference-backend or paper numbers alone.

## Exploratory bandit training with the engine (2026-11-10)

This is training and method development, separate from the confirmatory R1/R2
studies. Freeze `TaH-plus-0.6B`; select 500 complete MoT math/train solutions
with the existing seed-42 sampler, prompt cap 512 and reference cap 1024, with
normalized duplicate and lexical GSM8K/MATH500 overlap screening. This extends
the length-biased pilot population; it is not an independent test set.

Collect both depth-1 and depth-2 next-token losses on identical histories using
the engine's persistent cached passes, committing only native imitation routing
(threshold 0.9). Remove a speculative depth-2 KV entry whenever imitation stops.
Record checkpoint and engine source hashes. Require tiny-model branch-isolation
tests and real GPU unbranched replay before training. No benchmark test answers
are used for training, checkpoint selection or threshold fitting.

Split by normalized problem text with seed 42, 10% validation. Use the existing
five-penalty sweep (0, .01, .05, .1, .2), width 64, AdamW lr .0003, weight decay
.001, batch 512, 100-epoch maximum, patience 15, clip norm 1 and four CPU threads.
Select epoch, penalty and threshold by validation token NLL at imitation's
continuation budget. Report all curves; these are selected validation diagnostics,
not independent confidence intervals or answer accuracy. Do not extend training
based on an unfavorable result. Preserve the earlier 200-problem experiment.

Run imitation and selected-bandit 512-token greedy generation checks with the
same engine; selected routing applies during prefill and decoding. Record
truncation and actual pass counts; these smoke checks cannot support accuracy or
latency claims. Subsequent benchmark comparisons must freeze the engine and
rerun all compared policies on it. The focused 0.6B benchmark inputs, decoding
settings and final-answer grader are a separate comparison from the 1.7B R2
paper-reproduction baseline.
